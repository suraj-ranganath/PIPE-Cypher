# Structural difficulty score: calibration on v2 solve rates

Written 2026-11-12 (UTC). Generated by `scripts/calibrate_difficulty.py`. No model calls.

- Model: `configs/difficulty_v3.json`
- Code: `pipecypher/difficulty.py`
- Full numbers: `difficulty_calibration.json` (same directory)

## Data

- **Calibration items:** the 216 v2 held-out test items (`artifacts/benchmarks/naacl_v2_heldout/test.jsonl`), in 132 query-signature groups.
- **Target:** the fraction of 11 hosted models whose zero-shot, standard-prompt prediction is projected-EX correct (`artifacts/evaluations/naacl_v2_heldout_downstream_*`). Solve counts: 0 models on 43 items, 1-3 on 66, 4-7 on 57, 8-11 on 50.
- **Validation conditions:**
  - the governed zero-shot prompt (`*_promptfmt_*_zero_pipe_governed`);
  - few-shot (`*_control_*_ordered_logged`).

## Score

`score = sum(weight * min(feature, cap))`, computed on the reference Cypher with string literals masked. Tiers: **easy < 10 <= medium < 17 <= hard.**

| Feature | Weight | Cap |
| --- | ---: | ---: |
| returned columns | 2 | 6 |
| relationship hops | 2 | 4 |
| variable-length paths | 2 | 2 |
| negation (NOT, `<>`) | 2 | 2 |
| relationship-property / path-function reads | 2 | 3 |
| grouping keys next to an aggregate | 1 | 3 |
| temporal property or function references | 1 | 3 |
| ORDER BY | 1 | - |
| UNWIND / collect | 1 | 2 |
| WHERE conjuncts + inline property filters | 1 | 4 |
| distinct node labels | 1 | 4 |

**Fit.**

- Non-negative ridge regression of hardness (1 - solve rate) on capped counts. Lambda 0.3 was chosen by 5-fold CV grouped by query signature.
- Weights were rescaled so one returned column = 2 points, then rounded.
- Stages (WITH), OPTIONAL MATCH, and the aggregate count got zero weight.

**Out-of-fold Spearman with hardness:**

| Predictor | Spearman |
| --- | ---: |
| Continuous model | 0.570 |
| **Integer model** | **0.562** |
| Query length in tokens (single feature, unfitted) | 0.584 |
| Returned columns (single feature) | 0.535 |
| Hops (single feature) | 0.355 |
| Old heuristic | 0.282 |

Adding length to the model gives 0.574. It was not used: the gain is within noise, and length rewards verbose aliasing.

## For reviewers

We replaced v2's rule-of-thumb difficulty label, which marked 1 of 216 test items hard, with a transparent additive score. The score counts returned columns, relationship hops, variable-length paths, negations, relationship-property reads, grouping keys, temporal references, ordering, unwinding, filters, and labels.

The integer weights and the two thresholds were fit on how many of 11 downstream models solved each v2 held-out item, using cross-validation grouped by query signature. The score's out-of-fold rank correlation with hardness is 0.56, against 0.28 for the old label.

Out of fold, easy, medium, and hard items are solved by 65%, 31%, and 18% of models. The ordering holds for every one of the 11 models, under the governed prompt, and with few-shot examples.

The v3 planner sets per-(category, tier) quotas from this score. It reports any quota it cannot fill instead of relabeling items. Tiers on v3 items are re-validated on fresh solve rates, since v3 items were not used in calibration.
