# Graph Loading Plan

## Primary: LDBC FinBench

Rationale: FinBench is the primary graph because it models financial fraud and risk-control patterns with accounts, people, companies, loans, transfers, guarantees, and sign-in media. That is closer to enterprise Cypher workloads than public encyclopedic QA.

Implementation plan:

1. Fetch the LDBC sources with `scripts/fetch_ldbc_sources.sh external` and record commit hashes.
   - FinBench spec/docs: `https://github.com/ldbc/ldbc_finbench_docs`
   - FinBench datagen: `https://github.com/ldbc/ldbc_finbench_datagen`
   - Current fetched commits are recorded in `knowledge_base/ldbc_source_snapshot.md`.
2. Build and run the FinBench datagen at a small scale factor first, then inspect storage and import time.

   ```bash
   # On ds-serv6, fetch sources first because external/ is not rsynced.
   GIT_DEPTH=1 scripts/fetch_ldbc_sources.sh external

   # The fetched main-branch datagen starts at SF0.1.
   SCALE_FACTOR=0.1 \
   RUN_ROOT=/home/suraj/pipecypher-runs/finbench_sf0.1 \
   DATA_ROOT=/home/suraj/pipecypher-runs/finbench_sf0.1/data \
   scripts/run_finbench_datagen.sh
   ```

   The helper bootstraps Maven 3.9.9 and Spark 3.2.4 under `~/pipecypher-tools`, builds the datagen JAR, generates raw CSV data, transforms it with `transformation/snapshot.sql`, and writes `finbench_load.cypher`.

3. Copy or symlink the snapshot CSVs under the Neo4j import directory, for example `import/finbench/snapshot/*.csv`.
4. Generate the Neo4j import script when using a custom import path:

   ```bash
   python scripts/generate_finbench_import_cypher.py \
     --csv-base-url file:///finbench/snapshot \
     --output artifacts/import/finbench_load.cypher
   ```

   The script uses `MERGE` for nodes and `CREATE` for relationships. This is intentional: FinBench transfers, withdrawals, repayments, and deposits are event-like multiedges, so `MERGE` would collapse repeated transactions between the same endpoints. Clear the database before re-running the relationship import.
5. Start a local Neo4j Community 5.26 instance if one is not already available. Neo4j 5.26 LTS requires Java 17 or Java 21 according to the Neo4j Operations Manual (`https://neo4j.com/docs/operations-manual/current/installation/requirements/`), so `scripts/start_neo4j_community.sh` bootstraps a Temurin 17 JRE in user space on ds-serv6.

   ```bash
   RUN_ROOT=/home/suraj/pipecypher-neo4j \
   BOLT_PORT=7687 \
   HTTP_PORT=7474 \
   scripts/start_neo4j_community.sh
   ```

6. Load the FinBench snapshot into the Neo4j `neo4j` database for the community-edition smoke run:

   ```bash
   SNAPSHOT_DIR=/home/suraj/pipecypher-runs/finbench_sf0.1/data/snapshot \
   RUN_ROOT=/home/suraj/pipecypher-neo4j \
   scripts/load_finbench_neo4j.sh
   ```

   For paper-scale experiments, the config may still call the logical graph `finbench`, but the community smoke uses Neo4j's default `neo4j` database.

   The June 1, 2026 SF0.1 load completed with 10,006 nodes and 57,622 relationships:

   - Account: 3,810
   - Loan: 2,298
   - Medium: 1,950
   - Person: 980
   - Company: 968
   - TRANSFER_TO: 13,385
   - WITHDRAW_TO: 17,661
   - SIGN_IN: 5,976
   - DEPOSIT: 4,971
   - INVEST: 4,642
   - OWN_ACCOUNT: 3,810
   - REPAY: 3,654
   - APPLY_LOAN: 2,298
   - GUARANTEE: 1,225

7. For the community-edition smoke database, run `scripts/inspect_schema.py --config configs/finbench_live_smoke.yaml --output configs/schema_finbench.json`. This also infers low-cardinality string categorical values unless `--categorical-max-values 0` is supplied. For paper-scale experiments on a named database, use `configs/finbench_full.yaml`.
8. Run a smoke PIPE-Cypher generation pass on 1-2 examples per category before scaling. The June 1, 2026 live smoke accepted 4/4 examples with `configs/finbench_live_smoke.yaml`.

Minimum smoke checks:

```cypher
MATCH (n) RETURN DISTINCT labels(n) AS labels, count(*) AS count LIMIT 20;
MATCH ()-[r]->() RETURN DISTINCT type(r) AS relType, count(*) AS count LIMIT 20;
MATCH (a)-[r]->(b) RETURN DISTINCT labels(a), type(r), labels(b), count(*) LIMIT 50;
```

## Secondary: LDBC SNB

Rationale: SNB is a mature social-network graph benchmark with known graph workloads. It provides a generality check outside financial services.

Implementation plan:

1. Fetch the LDBC SNB sources with `scripts/fetch_ldbc_sources.sh external`.
   - SNB datagen: `https://github.com/ldbc/ldbc_snb_datagen_spark`
   - SNB Neo4j/Cypher implementations: `https://github.com/ldbc/ldbc_snb_interactive_v1_impls`
   - Current fetched commits are recorded in `knowledge_base/ldbc_source_snapshot.md`.
2. For a fast live smoke, use the official Cypher implementation's bundled `test-data/vanilla` CSVs. The helper `scripts/load_snb_neo4j.sh` runs `scripts/convert-csvs.sh`, then imports the converted typed-header CSVs with a custom `LOAD CSV` script generated by `scripts/generate_snb_import_cypher.py`.

   ```bash
   RUN_ROOT=/home/suraj/pipecypher-neo4j-snb \
   SESSION=pipecypher_neo4j_snb \
   BOLT_PORT=7688 \
   HTTP_PORT=7475 \
   AUTH_ENABLED=false \
   scripts/start_neo4j_community.sh

   RUN_ROOT=/home/suraj/pipecypher-neo4j-snb \
   BOLT_URI=bolt://localhost:7688 \
   scripts/load_snb_neo4j.sh
   ```

   The June 1, 2026 SNB test-data load completed with 34,735 nodes and 70,842 relationships.

3. Introspect schema into `configs/schema_snb.json`.

   ```bash
   /home/suraj/pipecypher-tools/runtime-venv/bin/python scripts/inspect_schema.py \
     --config configs/snb_live_smoke.yaml \
     --output configs/schema_snb.json
   ```

4. Run `configs/snb_live_smoke.yaml` first, then scale to `configs/snb_full.yaml` or a generated mini-ablation config.

   ```bash
   /home/suraj/pipecypher-tools/runtime-venv/bin/python scripts/run_pipeline.py \
     --config configs/snb_live_smoke.yaml \
     --run-name live_snb_qwen9b_ids_template
   ```

5. For larger runs, generate a manageable SNB scale factor or use the pre-generated `social_network-csv_composite-longdateformatter-sf*` datasets expected by the Cypher implementation.

## Third-Graph Onboarding Candidate: ICIJ Offshore Leaks

Rationale: ICIJ Offshore Leaks is a public real-world finance/compliance graph
with officers, offshore entities, intermediaries, addresses, source datasets,
relationship dates, and entity-resolution-style links. It is not a private
enterprise schema, but it is a stronger proxy for KYC/AML and investigative
industry settings than another synthetic benchmark. Use it to demonstrate
arbitrary-schema onboarding beyond FinBench/SNB once a live run has been loaded
and audited.

Implementation plan:

1. Fetch the current public data package and Neo4j dump:

   ```bash
   RUN_ROOT=/home/suraj/pipecypher-icij-offshoreleaks \
   FETCH_DUMP=true \
   scripts/fetch_icij_offshoreleaks.sh
   ```

2. Load the Neo4j dump into a separate Neo4j instance so FinBench/SNB runs are
   not disturbed:

   ```bash
   RUN_ROOT=/home/suraj/pipecypher-neo4j-icij \
   DOWNLOAD_DIR=/home/suraj/pipecypher-icij-offshoreleaks/downloads \
   SESSION=pipecypher_neo4j_icij \
   BOLT_PORT=7689 \
   HTTP_PORT=7476 \
   AUTH_ENABLED=false \
   scripts/load_icij_neo4j_dump.sh
   ```

3. Start the ICIJ backend on port 7689 and introspect the live schema:

   ```bash
   RUN_ROOT=/home/suraj/pipecypher-neo4j-icij \
   SESSION=pipecypher_neo4j_icij \
   BOLT_PORT=7689 \
   HTTP_PORT=7476 \
   AUTH_ENABLED=false \
   HEAP_INITIAL=6G \
   HEAP_MAX=12G \
   PAGECACHE=8G \
   scripts/start_neo4j_community.sh

   python scripts/inspect_schema.py \
     --config configs/icij_offshoreleaks_smoke.yaml \
     --output configs/schema_icij_offshoreleaks_live.json
   ```

4. Run `configs/icij_offshoreleaks_smoke.yaml` first. After a graph-backed dry
   pass accepts examples in every category, queue the target-100 live onboarding
   run in `configs/icij_offshoreleaks_full.yaml`.

Source and schema details are tracked in
`knowledge_base/icij_offshoreleaks_graph_plan.md`.
