\section{Reproducibility Evidence Map}
\label{tab:claim_evidence_map}
The entries below record the main empirical statements, the artifacts that support them, and the remaining risks that should be considered when reproducing or extending the study.
\begin{enumerate}
\item \textbf{Claim 1.} PIPE-Cypher can generate a private, executable NL-to-Cypher benchmark over enterprise-style property graphs using local models.\par
\textit{Evidence.} The full local Qwen3.5-9B run exported 3,000 accepted examples: 2,000 FinBench and 1,000 SNB, with 375 examples in every planned workload category and all accepted examples passing read-only, syntax, schema, execution, non-empty-result, and judge gates.\par
\textit{Key artifacts.} benchmark export; benchmark export; snapshot: clean qwen9b submission evidence manifest; paper table: benchmark export; +1 more\par
\textit{Status.} Supported by live local-model evidence.\par
\textit{Risk.} Generation quality may change with private enterprise schemas beyond FinBench/SNB.
\item \textbf{Claim 2.} Cypher-specific governance makes generated benchmark candidates safer and more auditable than prompt-only generation.\par
\textit{Evidence.} The pipeline validates read-only safety, schema-visible labels, node and relationship properties, relationships, observed relationship direction, categorical values, contextual return columns, parser-style structure, execution success, and LLM-judge review. In the clean full run, only 2 of 4,925 candidates were schema-invalid after deterministic governance, and all 3,000 exported examples passed the deterministic and judge gates.\par
\textit{Key artifacts.} code: validator.py; code: cypher\_parser.py; code: question\_constraints.py; snapshot: failure taxonomy; +1 more\par
\textit{Status.} Supported by code, tests, and full-run failure taxonomy.\par
\textit{Risk.} Semantic correctness still depends on execution evidence and judge review; the completed 80-row audit is a calibration sample rather than an exhaustive proof.
\item \textbf{Claim 3.} Reverse grounding and structured workload seeds are designed to improve reliability under local-model constraints.\par
\textit{Evidence.} Three FinBench/SNB ablation suites are complete and evidence-ready: the original target-50 suite, the corrected target-100 suite, and a seed-17 target-50 repeat. Each suite completed 14/14 graph/variant cells, reached every category target for all non-empty/non-unconstrained runs, and passed paper-readiness audits with logs, model IDs, code revisions, run summaries, collection manifests, and gate-rate availability. The target-100 suite is the detailed appendix ablation table/figure, while the three-suite comparison reports target-normalized coverage, acceptance variation, execution rates, and judge rates for stability.\par
\textit{Key artifacts.} script: run live ablation suite; script: monitor remote ablation suite; script: monitor remote ablation queue; script: collect remote ablation suite; +20 more\par
\textit{Status.} Supported by audited target-100 evidence and three-suite target-size/repeated-seed comparison.\par
\textit{Risk.} The repaired unconstrained local generation baseline produced accepted examples only in a narrow subset of categories: 200/422 accepted on FinBench across 2/8 categories and 50/2,000 accepted on SNB across 0/8 category targets. Comparisons against it should be framed as a gate-stress baseline rather than a tuned generation system.
\item \textbf{Claim 4.} The benchmark controls category and difficulty balance while exposing residual diversity limits.\par
\textit{Evidence.} The full export has perfect category balance, planned 2:1 FinBench/SNB graph mix, and a near-even easy/medium split. Diversity diagnostics report Distinct-n, sampled self-BLEU-2, query-signature diversity, normalized entropy, schema coverage, structural feature rates, and aggregate value-grounding diagnostics. The full export uses 1,115 unique grounded entity values and exactly quotes grounded values in 82.6\% of examples with entity bindings, making template and value concentration visible instead of hidden.\par
\textit{Key artifacts.} snapshot: diversity report; snapshot: diversity improvement comparison; paper table: diversity; paper table: diversity improvement; +2 more\par
\textit{Status.} Supported by full-export statistics and diversity diagnostics.\par
\textit{Risk.} Low query-signature diversity in the reported local-model run remains a limitation and ablation target.
\item \textbf{Claim 5.} The generated benchmark is useful for downstream Text2Cypher evaluation.\par
\textit{Evidence.} An 11-model completed local downstream evaluation over the 296-example full test split reports parse validity, schema validity, execution success, execution accuracy, answer F1, per-category breakdowns, model-transfer summaries, few-shot control runs, leakage audits, and row-level error taxonomies. Zero-shot execution accuracy ranges from 0.000 to 0.203 with a mean of 0.036. Few-shot controls over the same split improve the mean to 0.200 for a scored no-signature condition that excludes exact query-signature matches and near-duplicate questions, and to 0.269/0.267 for ordered/random same-category example banks. Model-level paired bootstrap intervals show that gains are concentrated in compatible model families rather than universal.\par
\textit{Key artifacts.} downstream summary; snapshot: downstream control manifest; snapshot: model transfer summary; snapshot: fewshot control summary; +12 more\par
\textit{Status.} Supported by live downstream evaluation against FinBench/SNB databases, with complete 11-model zero-shot/control summaries and leakage-aware few-shot controls.\par
\textit{Risk.} Several local fine-tuned checkpoints remain brittle under few-shot prompting; the current study shows example-bank utility and transfer failure modes, not a completed tenant-specific fine-tuning result. The stricter no-signature improvement is an aggregate signal with broad model-family uncertainty rather than a universal model-level gain.
\item \textbf{Claim 6.} Automated LLM-judge review can serve as a generation gate with post-hoc human calibration while still exposing judge risk.\par
\textit{Evidence.} The pipeline uses deterministic validation plus LLM-judge review as the generation gate. A post-hoc 80-row judge audit packet preserves 40 judge accepts, 40 judge rejects, both graphs, and all eight categories. The completed human audit reports 80.0\% agreement, Cohen's kappa 0.60, balanced accuracy 0.857, judge precision 1.00, judge specificity 1.00, judge recall 0.714, zero false accepts, and 16 false rejects. The analyzer requires complete labels for calibration, and the tracked summary avoids committing raw value-bearing audit rows.\par
\textit{Key artifacts.} code: judge.py; code: calibration.py; code: judge\_audit\_packet.py; script: create judge annotation sheets; +3 more\par
\textit{Status.} Supported by completed human audit summary.\par
\textit{Risk.} The judge appears conservative on this sample; larger audits or different enterprise schemas may reveal false accepts.
\item \textbf{Claim 7.} PIPE-Cypher supports arbitrary enterprise schema onboarding with configurable privacy redaction and value-sampling policies.\par
\textit{Evidence.} The repo includes an enterprise deployment guide, an enterprise template config, privacy config fields, schema introspection that reads categorical-value thresholds, maximum sampled value length, and omitted-property patterns from config, deterministic redaction helpers, and a redacted benchmark export CLI. The redaction policy replaces quoted Cypher literals, question mentions, entity values, and string-valued result samples with stable placeholders while preserving query structure and gate metadata. The repo now also includes an ICIJ Offshore Leaks onboarding profile, config, download/load helpers, graph plan, schema-derived sparse-category templates, and a completed sanitized target-100 onboarding audit on a public finance/compliance graph beyond the LDBC study workloads.\par
\textit{Key artifacts.} research note: enterprise deployment guide; research note: icij offshoreleaks graph plan; enterprise\_template.yaml; schema\_icij\_offshoreleaks.json; +21 more\par
\textit{Status.} Supported by docs, config, code, deterministic tests, a concrete third-graph onboarding plan, and a completed sanitized ICIJ target-100 live onboarding run with 800/983 accepted examples and 8/8 categories at target.\par
\textit{Risk.} ICIJ is public rather than private/anonymized enterprise data. The strongest industry validation would still come from a real tenant graph under the same audit protocol.
\end{enumerate}
